# JSM 業務フロー デモ

Jira Service Management で構築する「社内申請・承認・制作工程管理」の設計方針を、ブラウザで操作できる形にしたデモです。
`index.html` をブラウザで開くだけで動作します（ビルド・サーバー不要、データはブラウザ内に保存）。

> 本リポジトリは、クラウドワークスの案件 https://crowdworks.jp/public/jobs/13591314 への応募に際し、提案内容の具体例として作成したものです。
> 設計のモック（`index.html`）と、実際の Jira Cloud 上での構築記録（[`jira/README.md`](jira/README.md)）を含みます。

## 体験の流れ（約3分）

1. **田中（申請者）** で「備品購入申請」→ 金額 `150000` を入力 → 承認経路に部長が追加されることを確認して申請
2. 右上の表示ユーザーを **佐藤 課長** に切替 → 承認キューから承認（または差戻し）
3. **鈴木 部長** で承認 → 担当者がマスタから自動割当
4. **山本（総務）** で対応開始 →「回答待ち」にすると解決SLAが停止
5. **Jira管理者** でダッシュボード（滞留・SLA超過・改善提案）とマスタ管理を確認
6. マスタで佐藤課長を「不在」にして再度申請 → 代理承認者（加藤）へ自動回付

「+8時間」ボタンで時間を進めると、SLA超過の発生とダッシュボードの変化を確認できます。

## 実装している要素

| 募集要件 | デモでの対応 |
|---|---|
| 申請フォーム・条件分岐・必須項目 | 申請種別ごとの項目定義、条件表示（媒体=動画→尺、GitHub→リポジトリ名）、必須チェック |
| 承認経路・代理承認・差戻し/再申請 | 金額閾値による部長承認追加、不在時の代理回付、差戻し→修正→経路再評価 |
| 自動割当・親子チケット・通知 | マスタ参照の担当割当、工程別子チケット自動生成、全子完了で親を自動完了、通知ログ |
| 閲覧権限・操作権限 | 申請者/承認者/実行担当/管理者で見えるチケット・操作・タブを制御 |
| マスタを変更しやすい運用 | Automationは担当者名を持たずマスタ参照のみ。変更履歴も記録 |
| SLA（開始・停止・回答待ち） | 承認SLA・解決SLAを状態履歴から算出、回答待ち・差戻し中は停止 |
| ダッシュボード・JQL・改善提案 | 状態別滞留、担当者別件数、工程別作業時間、超過一覧、各集計のJQL、計測値に基づく提案 |
| テスト・リリース・切戻し | 設計書タブにテスト観点、リリース/切戻し/障害調査手順 |
| 将来の移行整理 | 業務要件／Jira実装／移行先実装の対応表、データ項目定義 |

## 設計上のポイント

- **フォーム定義・承認ルール・割当ルールをデータとして保持**（`REQUEST_TYPES` / `defaultMaster()`）。Jira上ではRequest Type・Assets・Automationに分散する設定を、移行先でもそのまま仕様として使える形で整理。
- **SLAは状態履歴から算出**（`timeIn()`）。Jira依存のSLA設定を、移行先でも再現できるロジックとして明文化。
- **個別カスタマイズを避ける**：標準機能（ワークフロー・承認・Automation・SLA）＋マスタ参照の組合せで実装し、保守性と移行性を確保。

※ `index.html` は設計の考え方を示すためのモックです。同じ設計を実際の Jira Cloud 上に構築した記録は [`jira/README.md`](jira/README.md) にあります。
